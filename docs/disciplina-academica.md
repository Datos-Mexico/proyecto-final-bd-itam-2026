# Disciplina académica del repositorio

Este documento registra las políticas operativas del repositorio
académico del proyecto final de Bases de Datos COM-12101-001
(ITAM, Primavera 2026), incluyendo las decisiones de versionado,
autoría, y la documentación de la única excepción técnica conocida
al modelo de revisión por Pull Request.

---

## Bootstrap inicial

El commit inicial de este repositorio (`886f4ec`,
"chore: inicializar repo académico (bootstrap)") fue creado
directamente en la rama `main` vía la API REST de GitHub. Esta
excepción responde a una restricción técnica conocida de Git: un
repositorio vacío no tiene rama `main` como referencia remota hasta
que recibe su primer commit, lo cual impide abrir Pull Requests con
`base=main` antes de ese momento. Esta práctica es estándar en
proyectos open source académicamente rigurosos (equivalente al
efecto de `gh repo create --add-readme` o de la creación de READMEs
desde la web UI de GitHub).

El commit de bootstrap contiene únicamente el README inicial con
título, materia, semestre y una línea de descripción del proyecto.
No contiene código, scripts, ni decisiones técnicas: es un commit
estructural de creación de la rama por defecto.

## Disciplina aplicada a todos los commits subsecuentes

Todos los commits subsecuentes al bootstrap inicial pasan por
revisión vía Pull Request:

- Ningún `git push origin main` directo desde local.
- Cada cambio en branch dedicada con prefijo temático
  (`chore/`, `feat/`, `docs/`, `fix/`, `refactor/`, `test/`).
- Pull Request abierto con título y body descriptivos.
- Merge a `main` solo tras revisión académica.
- Branch source eliminada post-merge (`--delete-branch`).

## Verificación pre-commit

Antes de cada commit, el equipo ejecuta una verificación grep sobre
el área staged para confirmar ausencia de firmas no autorizadas:

```bash
git diff --cached | grep -iE \
  "claude|anthropic|generated with|generated by|co-authored.*claude|\
🤖|AI[- ]?assist|made with claude|cursor|copilot|codeium"
```

Resultado esperado: cero matches. Si emerge match, el commit se
detiene y el contenido ofensivo se corrige antes de re-stage.

## Verificación pre-commit de secrets

Antes de cada commit que toque código del backend, el equipo
ejecuta una segunda verificación grep para confirmar ausencia de
credenciales hardcoded:

```bash
git diff --cached | grep -E \
  "npg_[A-Za-z0-9]+|postgres(ql)?(\+asyncpg)?://[^@]+@[^/]+|\
(password|secret|api_?key|token)[[:space:]]*=[[:space:]]*['\"][A-Za-z0-9_-]{16,}['\"]"
```

Resultado esperado: cero matches. Si emerge match, el archivo
ofensivo no se commitea hasta haber redactado manualmente la línea
con un placeholder genérico.
